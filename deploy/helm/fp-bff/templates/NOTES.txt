1. Watch the rollout reach Ready:

   kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "fp-bff.fullname" . }}

2. Check pod health:

   kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}

3. Probe the health endpoints (port-forward the HTTP health port):

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "fp-bff.fullname" . }} {{ .Values.ports.health }}:{{ .Values.ports.health }}
   curl -s localhost:{{ .Values.ports.health }}/healthz   # liveness
   curl -s localhost:{{ .Values.ports.health }}/readyz    # readiness (+ checks it can reach auth + registry over gRPC)

4. Exercise the HTTP API (port-forward the API port):

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "fp-bff.fullname" . }} {{ .Values.ports.http }}:{{ .Values.ports.http }}
   # Login (public) → returns an access token:
   curl -s -X POST localhost:{{ .Values.ports.http }}/api/v1/login \
        -H 'Content-Type: application/json' \
        -d '{"email":"admin@forgepoint.local","password":"<bootstrap-password>"}'
   # List models WITH the bearer token (protected) → 200:
   curl -s localhost:{{ .Values.ports.http }}/api/v1/models -H 'Authorization: Bearer <token>'
   # List models WITHOUT the token → 401 (default-deny on the protected sub-tree).

SECRETS: none. The BFF holds NO Secret — it FORWARDS the caller's JWT to the
   downstream services (which validate it with the shared secret). It never mints
   or validates tokens, has no DB DSN, and no signing key.
